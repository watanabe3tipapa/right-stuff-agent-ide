# エージェント向けガイドライン

このファイルは、AI コーディングエージェントがこのリポジトリで作業するときの
共通ルールです。プロジェクト固有の事情に合わせて追記してください。

## 基本方針

- 変更は小さく保ち、目的が一つのコミットにまとめます。
- 既存の構造、命名、スタイルを優先します。
- 不明なファイルや変更は、削除する前に必ず確認します。
- 生成したコードだけでなく、テストとドキュメントも更新します。
- 推測で外部サービスを呼び出しません。設定と承認を確認します。

## 作業の進め方

1. 関連するファイルとテストを読む。
2. 変更方針を短く書き、影響範囲を確認する。
3. 実装とテストを同時に進める。
4. typecheck、lint、test を実行する。
5. 失敗した検証は、原因を記録してから修正する。
6. 変更内容と検証結果をレポートに残す。

## 日本語の表記

- 用語は `docs/GLOSSARY.md` に従います。
- 全角の英数字と半角カタカナを使いません。
- 行頭に閉じ括弧や句読点を置きません。
- 行末に開き括弧を置きません。
- コードブロック、インラインコード、URL は表記チェックの対象外です。
- 日付は `YYYY年MM月DD日` 形式にします。

## やってはいけないこと

- 承認なしにファイルを書き換える。
- テストを削除して通す。
- 秘密情報、鍵、`.env` を LLM やログへ送る。
- `node_modules`、`target`、`.git` を編集する。
- 破壊的な Git 操作を確認なしに実行する。
- 失敗した検証を無視して完了扱いにする。
