GitHub Repository Deep Dive

Openship 詳細解説

オープンソースのセルフホスト型デプロイメントプラットフォーム。
リポジトリを指定するだけで、ビルド・デプロイ・ルーティング・TLS終端までを一気通貫で実行する。

01 プロジェクト概要

Openship は、oblien によって開発されているオープンソースのセルフホスト型デプロイメントプラットフォームです。GitHub リポジトリ、ローカルフォルダ、またはビルド済みアーティファクトをソースとして指定すると、自動検出・ビルド・実行・リバースプロキシ・TLS設定までを自動化する CI/CD 機能を内包しています。

デスクップアプリ、Web ダッシュボード、CLI、SDK（JavaScript/TypeScript）の4つのインターフェースから操作でき、個人開発者からチーム運用まで幅広く対応します。

  • リポジトリ: oblien/openship
  • ライセンス: Apache License 2.0
  • 最新バージョン: v0.9.7（2026年11月1日時点）
  • 主要スタック: Bun / Node.js 22+ / Docker / OpenResty / Postgres / Redis

02 主な機能と特徴

自動検出（Zero Config）

package.json、フレームワク設定ファイル、ロックファイル、docker-compose.yml / openship.json を読み取り、スタック・パッケージマネージャー・ビルド/起動コマンド・ポートを自動判定します。設定ファイルがなくても動作し、必要に応じて openship.json で上書き可能です。

ビルドとスナップショット

ターゲットサーバー上またはオーケストレータ上で Docker イメージまたはベアリリースとしてビルドします。解決された設定はスナップショットとして凍結されるため、再デプロイやロールバック時に「その時点の完全同一の構成」が再現されます。

ルーティングと TLS

OpenResty ベースのエッジサーバーがリバースプロキシ用 vhost を自動生成し、Let's Encrypt（HTTP-01）で証明書を発行します。ルーティングと TLS はアプリ起動後に行われるため、DNS や証明書の問題がデプロイ失敗を引き起こすことはありません。

Push-to-Deploy

GitHub Webhook と連携し、追跡中のブランチへのプッシュごとにパイプラインを再実行します。モノレポの場合、変更のあったサービスのみ再ビルドします。

統合管理

データベース、ドメイン、SSL、CDN、メール、ックアップを同一ダッシュボードから管理できます。

03 動作モードの比較

Openship 自身の「コントロールプレーン」をどこで動かすかで、3つの形態が選べます。

形態対象ユーザー特徴
Desktop app 個人 / 単一マシン ローカルでコントロールプレーンが動作。SSH でサーバーを操作。公開ポートなし。アプリ起動中のみ有効。
Self-hosted server チーム / 常時稼働が必要 Linux サーバー上で常時稼働。公開 URL + ログイン必須。CI/CD、チーム招待、同一ボックスでのホスティングが可能。
Openship Cloud 運用を任せたい場合 マネージドサービス。ゼロセットアップで用可能。

04 デプロイメントパイプライン

Openship は、ソースを指定すると以下の5段階を自動実行します。

  1. Detect（検出）: プロジェクト構成を自動解析し、フレームワーク・コマンド・ポートを決定。
  2. Build（ビルド）: Docker イメージまたはベアリリースとしてビルド。構成はスナップショット化。
  3. Run（実行）: コンテナ（ループバックのみ公開）または監視下ホストプロセスとして起動。
  4. Route + Secure（ルーティングと保）: OpenResty エッジがドメイン用 vhost と Let's Encrypt 証明書を自動設定。
  5. Push-to-Deploy: GitHub プッシュをトリガーにパイプライン再実行。モノレポ差分に応じた部分ビルド。

06 インストール方法

A. デスクトップアプリ（推奨: 個人利用）

OS ごとのバイナリをダウンロードするか、CLI で openship install を実行します。

  • macOS (Apple Silicon): Openship-arm64.dmg
  • macOS (Intel): Openship-x64.dmg
  • Windows: Openship-win32-x64.zip
  • Linux: Openship.AppImage

B. セルフホストサーバー（チーム / 常時稼働）

CLI をインストール後、対話式ウィザードでセットアップします。

# インストール
curl -fsSL https://get.openship.io | sh

# 対話式セットアップ + コントロールパネル起動
openship

# またはワンライナーでバックグラウンドサービスとして起動
openship up --public-url https://openship.example.com --managed-edge

C. Docker Compose（CLI なし）

ビルド不要で公開済みイメージをプルして起動します。

git clone https://github.com/oblien/openship.git && cd openship
cp .env.example .env
# .env を編集後
docker compose --env-file .env -f docker/docker-compose.yml up -d

スタック構成: Postgres + Redis + API + Dashboard + OpenResty Edge（:80/:443）。Linux のみ対応（host networking 使用）。

09 まとめ

Openship は、「リポジトリを指定するだけ」で本番環境の構築から TLS 設定までを自動化する、現代的なセルフホスト型 PaaS です。特に以下の点が優れています。

  • 運用形態の柔軟性: デスクトップアプリからフルマネージド Cloud まで、利用規模に応じて3形態から選択可能。
  • Zero Config: 既存プロジェクトに設定ファイルを追加せずとも、フレームワークを自動検出してデプロイ可能。
  • 安全性の設計: TLS や DNS の問題がデプロイ失敗を引き起こさない「事後ルーティング」設計。
  • モノレポ対応: 変更のあったサービスのみ再ビルドする効率的な Push-to-Deploy。

個人開発者にはデスクトップアプリ、チーム運用には openship up によるセルフホスト、手軽さを重視する場合には Cloud と、用途に応じた選択肢を提供している点が大きな魅力です。
