# Security

## パス検証

すべてのファイル操作は Rust 側で次の検証を通る。

1. 相対パスのみ許可。絶対パスと `..` を含むパスは `OutsideWorkspace` エラー。
2. 既存パスは `canonicalize` した上でワークスペースルート配下か確認する。
3. 新規パスは最も近い既存の祖先を `canonicalize` して同じ確認を行う。
4. シンボリックリンクはファイルツリーに列挙しない。

これにより、UI やエージェントが `../../.ssh/id_rsa` のようなパスを渡しても
バックエンドで拒否される。

## ファイル書き込み

- 同一ディレクトリに一時ファイルを書いてから `rename` する atomic write。
- 保存のたびに SQLite へ内容を記録する (最新 100 版 / ファイル)。
- 削除は即時削除ではなく `<workspace>/.right-stuff/trash/<timestamp>/` へ移動する。
- `.right-stuff` 自体は削除できない。

## エージェント操作

### モード

| モード | ファイル読み書き | チャット | 外部アプリ操作 |
| --- | --- | --- | --- |
| Passive | 読み取りのみ | なし | なし |
| Assistive | 可 (危険操作は承認) | 可 | 承認フロー経由 (手順ごと) |
| Autonomous | 可 | 可 | 承認フロー経由 (連続) |

### 承認が必要な操作

`agent_run` / `agent_snapshot` は次の三段階で防御する。

1. **引数検証** — アクション名の許可リスト、引数個数（最大 12）、1 引数あたりの長さ（最大 16,384 文字）、合計長（最大 32,768 文字）、NUL 文字の拒否。`launch` / `close-app` はアプリ名 1 つだけを許可し、パス区切り・`..`・先頭 `-` を拒否する。`type` / `set-value` / `clipboard-set` は内容の存在を必須にする。
2. **ポリシー判定** — SQLite に保存されたエージェントポリシーを実行のたびに読み直す。`block` は CLI を起動せず拒否し、`ask` は次の承認へ進む。読み取り専用アクションだけが `allow` を選べ、変更アクションは `ask` / `block` に限る。ポリシーの未知アクションや変更アクションの `allow` は保存時に拒否する。
3. **ネイティブ承認** — ポリシーが `ask` のアクションは、実行直前に OS の確認ダイアログを表示する。ダイアログには実行するコマンドを表示し、承認した場合のみ CLI を起動する。既定では読み取り専用アクションが `allow`、変更アクションが `ask`。

CLI はシェルを介さず `Command::new(binary).args(args)` で直接起動するため、シェルインジェクションは成立しない。

### 出力

- `agent_run` の stdout / stderr は 200,000 文字で打ち切る。
- コマンドは UI に `command[]` として表示し、何を実行したか追跡できるようにする。

### 監査ログ

- 監査ログはローカルの SQLite にのみ保存し、外部へ送信しない。
- 記録対象は計画の作成・承認・却下・中止、操作の実行・拒否・キャンセル、ポリシー変更。操作の記録にはコマンド引数、結果、失敗時の stderr / エラー抜粋が含まれる。
- API キー、LLM のプロンプトと応答、ファイル内容は記録しない。
- 詳細は 4,000 文字、引数は合計 32,768 文字で検証・打ち切り、NUL 文字は拒否する。
- 監査ログを無効にしても既存の記録は残る。保持期間（既定 30 日）と最新 5,000 件を超えた記録は次の記録時に削除する。
- バックアップやログ共有の際は、コマンド引数やエラー本文に機密情報が含まれうる点に注意する。

### 計画の承認

- LLM が返した計画は信頼せず、`src/lib/plan.ts` で `agent_run` と同じ許可リスト・
  引数規則を使って検証する。不正なアクションや引数を含む計画は UI に表示しない。
- リスク（読み取り / 変更）はモデルの自己申告ではなく、許可アクションの
  読み取り専用リストから決定する。
- 計画の承認は UI 上の実行可否を決める状態であり、`agent_run` の再検証と
  変更操作のネイティブ承認を置き換えない。計画を承認しても、変更操作は
  実行のたびに OS のダイアログで確認する。
- 計画は最大 12 手順。手順ごとの出力は 8,000 文字で打ち切って表示する。
- 計画本体と stdout 全体はメモリ上にのみ保持する。監査ログには計画の状態遷移と、実行したコマンド・結果・失敗時のエラー抜粋のみを記録する。

## LLM 接続と API キー

- LLM への HTTP 通信は WebView ではなく Rust 側で行う。CSP の `connect-src` に外部オリジンを追加しない。
- API キーは OS キーチェーン（macOS は Keychain Services）にのみ保存する。キーはプロバイダーごとに 1 つ保持する。
- SQLite にはプロバイダー名・Base URL・モデル名・Temperature・最大トークン数のみを保存する。API キーは保存しない。
- `llm_config_get` / `llm_key_status` が返すのは「設定済みかどうか」の真偽値だけ。キー本文は WebView に返さない。
- キーはログ・エラー文字列・監査ログに出力しない。キーチェーン操作の失敗は一般的なメッセージに置き換える。
- Base URL は `https://` を必須とし、`http://` は `localhost` / `127.0.0.1` / `::1` のみ許可する。URL にユーザー名・パスワード・クエリ・フラグメントは含められない。
- メッセージは role の許可リスト、1 件あたり 100,000 文字、合計 400,000 文字、最大 100 件で検証する。
- ストリーミングは `llm_cancel` で協調的に停止できる。

### 送信範囲

- 現在のチャットは、ユーザーが入力したプロンプトと直近 20 件の会話だけを送信する。
- 計画立案では、Plan タブに入力した意図と計画用システムプロンプトだけを送信する。
- ローカル通知、コマンド出力、システムメッセージ、`/status` などのローカルコマンドは履歴から除外する。
- ワークスペースのファイル、デスクトップスナップショット、クリップボードの内容を自動で送信しない。
- ローカルプロバイダー（Ollama / LM Studio）は `http://localhost` を許可するが、外部ホストへの平文 HTTP は拒否する。
- プロバイダーが返したエラー本文に API キーが含まれる場合は、WebView へ渡す前に `[REDACTED]` へ置換する。
- 接続テストなどで読み取る HTTP レスポンス本文は 1 MiB で打ち切る。
- HTTP リダイレクトには追従しない。API キーの送信先を Base URL のホストに固定するため。

## Openship 連携

- 接続設定（Base URL・組織 / プロジェクト ID・ブランチ・CLI パス）は SQLite の `openship_config` に保存する。PAT は OS キーチェーン（`com.rightstuff.agentide.openship`）にのみ保存し、WebView には真偽値だけを返す。
- 通信は Rust 側で行い、WebView から Openship へ直接接続しない。CSP の `connect-src` は変更しない。
- Base URL は `https://` を必須とし、`http://` は `localhost` / `127.0.0.1` / `::1` のみ許可する。URL にユーザー名・パスワード・クエリ・フラグメントは含められない。
- プロジェクト ID・デプロイ ID・ブランチ名は英数字と `-` / `_` に制限する。CLI 実行時は配列引数で渡し、シェルを介さない。
- `deploy` と `rollback` は変更操作として扱い、Passive モードでは拒否する。Assistive / Autonomous でもネイティブ承認ダイアログを必ず表示し、`agent_policy` で省略できない。
- 実行したコマンド・終了コード・失敗時の出力抜粋は監査ログに記録する。PAT とレスポンス本文全体は記録しない。
- CLI は `cliPath`、`OPENSHIP_BIN`、`PATH` の順に検出する。設定された CLI パスは実行ファイルとして存在するか確認する。
- REST はセルフホストの Openship を想定する。履歴・ログの取得は読み取り操作、デプロイ・ロールバックは承認必須の変更操作として扱う。

## Git 連携

- `git` CLI をワークスペースルートから `std::process::Command` で直接実行する。シェルを介さず、ユーザー入力をコマンド文字列へ連結しない。
- ステージ / ステージ解除 / 差分の対象パスは `paths::validate_relative` で検証し、絶対パスと `..` を拒否する。ワークスペース外のファイルは操作できない。
- コミットメッセージは空文字と 5,000 文字超を拒否する。改行はそのまま 1 つの引数として渡す。
- `git_status` は `--porcelain=v2 --branch --untracked-files=all`、差分は `--no-color --unified=3` を使い、出力は 200,000 文字で打ち切る。
- `GIT_TERMINAL_PROMPT=0` を設定し、認証待ちでアプリが停止しないようにする。Git の通信・認証情報は OS / Git の設定に従う。
- ステータス・差分・履歴はローカルでのみ扱い、外部へ送信しない。

## 統合ターミナル

- 起動するシェルは `RIGHT_STUFF_SHELL` → `SHELL` → `/bin/zsh` の順で解決し、絶対パスかつ存在する実行ファイルのみ許可する。相対パスや存在しないパスは拒否する。
- 作業ディレクトリはワークスペースルートに固定する。ユーザーがシェル内で移動した後の挙動は通常のシェルと同じ。
- PTY の出力は Tauri イベント (`terminal://output`) で WebView へ渡すだけで、ネットワークへ送信しない。
- ターミナルは Tauri 版でのみ有効。ブラウザデモでは起動しない。
- セッションは `AppState.terminals` で管理し、ターミナルを閉じたとき、再起動したとき、アプリ終了時に子プロセスを kill する。
- PTY はユーザーが起動したシェルであり、シェル内で実行されるコマンドはアプリの承認フローや監査ログの対象外である。

## スキル実行（Git / ターミナル / デバッグ）

- 実行できる操作は v1 マニフェストの `handler` 名から Rust の固定関数へディスパッチする。マニフェストから任意のコマンド文字列やシェルを受け取らない。
- 承認はマニフェストの `approval` と `skill_policy` で決める。`allow` は読み取り専用アクションに限り、`ask` はネイティブ承認ダイアログを表示し、`block` と受動モードは実行しない。
- Git ハンドラは `status` / `diff` / `branches` / `stage` / `stageAll` / `commit` のみ。`push` / `reset --hard` / `checkout` は含めない。パスはワークスペース内の相対パスに限定し、`*_at` ヘルパー経由で `git` CLI を配列引数で実行する。
- ターミナルハンドラ `terminal.run` は `npm` / `pnpm` / `yarn` / `cargo` / `node` / `python3` / `pytest` / `make` だけを、`program + args` で直接実行する。シェル文字列、パイプ、リダイレクトは組み立てない。引数は 32 件・各 512 文字まで。
- ターミナルと検証の子プロセスは `process_group(0)` で独立したプロセスグループに入れ、タイムアウト時はグループごと SIGKILL する。出力は `limits.maxOutputChars` で打ち切る。
- 非ゼロ終了とタイムアウトは `HandlerOutcome.failed` として返し、`SkillRunStatus::Failed` と `errorCode: "handler_failed"` になる。監査ログの outcome は `error` とする。
- デバッグハンドラは固定レジストリの `lldb-dap` / `debugpy` だけを起動し、Debug タブと同じセッションを `sessionId` で共有する。`debug.start` は initialize → launch → initialized → configurationDone の順で進み、失敗時はセッションを kill して state から削除する。
- 検証ループは `package.json` / `Cargo.toml` から解決した固定のコマンドだけを実行し、マニフェストから任意のコマンドは受け取らない。

### HTML レポート

- レポートは WebView の `src/lib/report.ts` で生成し、Rust の `report_export` は保存だけを担当する。レポート内容を外部へ送信しない。
- 保存先はワークスペース内の `.agents/reports/*.html` に限定する。ファイル名は先頭 `.`、パス区切り、`..`、`/` を拒否し、英数字と `.` `_` `-` のみを許可する。拡張子は `.html` 必須で、HTML は 4 MB まで。書き込みは `atomic_write` を使う。
- スキル名・説明・パラメータ・stdout / stderr・変更ファイル・検証コマンド / 出力・監査 ID など、すべての可変値を `escapeHtml` でエスケープする。
- レポート内の JavaScript はテーマ切替の固定コードだけで、可変値を script に埋め込まない。外部 CSS / JavaScript / 画像は参照しない。
- プレビューは `sandbox="allow-scripts"` の iframe で行い、同一オリジン権限を渡さない。
- レポートには実行時のパラメータと出力が含まれるため、共有する場合は機密情報が含まれていないか確認する。

## LSP / DAP

- 起動できるプログラムは固定レジストリに限定する。LSP は rust-analyzer / typescript-language-server / pyright / gopls / clangd / sourcekit-lsp / lua-language-server、DAP は lldb-dap / debugpy のみで、WebView から任意のコマンドや引数を指定することはできない。
- サーバー / アダプターはシェルを介さず、配列の引数で `std::process::Command` から起動する。
- デバッグ対象の `program` は絶対パスまたはワークスペース内の相対パスに限り、`paths::validate_relative` と `canonicalize` でワークスペース外を拒否する。
- LSP / DAP の通信はローカルの子プロセスとの間だけで完結し、外部ネットワークへ送信しない。
- Content-Length は 16MB、stderr ログは 1 行 8KB で打ち切り、壊れたフレームや巨大なメッセージでメモリを消費しないようにする。
- LSP の `workspace/applyEdit` はワークスペース内のテキスト編集だけを適用する。ファイルの作成・名前変更・削除を伴うリソース操作は拒否し、`applied: false` を返す。
- セッションは `AppState.lsp_sessions` / `AppState.dap_sessions` で管理し、ワークスペース切替時とアプリ終了時にすべて kill する。
- LSP サーバー / デバッグアダプター自体の脆弱性や、デバッグ対象プログラムの挙動はアプリの保証範囲外である。信頼できるワークスペースでのみ利用する。

## CSP と HTTP ヘッダー

- Tauri は本番用 `csp` と開発用 `devCsp` を分けて設定する。本番は `default-src 'self'` を基底とし、Monaco の worker 用に `worker-src 'self' blob:`、Google Fonts 用に `font-src`、Tauri IPC 用に `connect-src ipc: http://ipc.localhost` を許可する。
- Vercel は `Content-Security-Policy`, `X-Frame-Options: DENY`, `Permissions-Policy`, `X-Content-Type-Options`, `Referrer-Policy` を全レスポンスへ付与する。
- `frame-ancestors 'none'` と `X-Frame-Options: DENY` でクリックジャッキングを防ぐ。

## スナップショットとプライバシー

- スナップショットは現時点ではメモリ上にのみ保持し、SQLite へ永続化しない。
- LLM へ自動送信するのはチャットの会話のみ。スナップショットやファイル内容は送信しない。
- 今後、以下を追加する:
  - 銀行・メールクライアント等の機密ウィンドウの自動マスク
  - LLM 送信前のパス・ユーザー名の匿名化
  - 永続化の明示的なオプトイン
- テレメトリは送信しない。

## 保存データ

| データ | 場所 |
| --- | --- |
| ワークスペースのファイル | ユーザーが選んだフォルダ |
| バージョン履歴・LLM 設定・エージェントポリシー・Openship 設定・監査ログ | OS の app data ディレクトリ内 `right-stuff.db` |
| エージェントモード | WebView の `localStorage` |
| API キー・Openship PAT | OS キーチェーン |
| ターミナルの PTY | メモリ上のみ（再起動で消滅） |
| LSP / DAP のセッション、ブレークポイント、出力 | メモリ上のみ（再起動で消滅） |
| スキル実行の HTML レポート | ワークスペース内 `.agents/reports/*.html` |

`right-stuff.db` は WAL モードで開く。履歴にはファイル内容が、監査ログには
コマンド引数と失敗時のエラー抜粋が含まれるため、バックアップや共有の際は
注意する。

## 既知の制約

- LLM は OpenAI 互換 API のみ対応する。Anthropic 固有の API は未対応。
- 計画の実行対象は Agent Desktop の許可アクションと、マニフェストで宣言したスキルに限る。スキルから実行できるのはエディタ・Git・許可プログラム・DAP の固定ハンドラのみ。
- 計画本体と stdout 全体はメモリ上にのみ保持され、再起動すると失われる。監査ログに残るのは状態遷移と実行メタデータのみ。
- 監査ログのエクスポート・改ざん検知・外部 SIEM 連携は未実装。
- API キーのローテーションや複数キーの管理は未実装。
- Git の merge / rebase / push と認証情報の管理は未実装。Git パネルと Git スキルの操作は監査ログに記録する。
- `skill_cancel` と実行中検証のキャンセルは未実装。
- 統合ターミナル内のコマンドはアプリのポリシー・承認・監査ログの対象外。信頼できる作業ディレクトリでのみ利用する。
- LSP は補完・定義・ホバー・診断・名前変更・参照検索・コードアクション・シンボル検索に対応する。DAP は起動・停止・ステップ実行・ブレークポイント・変数表示のみで、attach と条件付きブレークポイントは未対応。

## 依存関係の監査

デスクトップアプリは macOS 専用だが、`Cargo.lock` には Tauri の Linux 向け依存（GTK / WebKit など）も解決結果として含まれる。これらは macOS ビルドではコンパイルされないが、Dependabot と `cargo audit` は lockfile 全体を対象にするため、警告が表示されることがある。

macOS の依存ツリーに含まれない crate の警告は `not_used` として扱い、必要に応じてこの節に記録する。現在の該当例は `glib`（RUSTSEC-2024-0429、Linux 専用の Tauri 依存）で、macOS ビルドには含まれない。
