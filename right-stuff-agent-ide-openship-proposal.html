Technical Proposal

Right-Stuff Agent IDE x Openship
連携技術提案書

エージェント駆動型デスクトップ IDE からセルフホスト型デプロイメント基盤へ橋渡しする統合手法の考察

01前提と目的

本提案は、right-stuff-agent-ide（以下 RSIDE）側からのアプローチで、Openship と連携させる手法を考察するものです。 RSIDE は Tauri 2.0 + React 18 + Monaco Editor + Rust で構築されたエージェント駆動型デスクトップ IDE です。 Openship は、Git リポジトリやローカルフルダからビルド・デプロイ・ルーティング・TLS 終端までを担うセルフホスト型デプロイメントプラットフォームです。

両者を連携させることで、「エディタで書く → エージェントに任せる → デプロイする → 結果を確認する」という一連の流れを、同一ワークスペース内で完結させることを目指します。

03推奨連携アーキテクチャ

RSIDE 側から Openship を操作するには、以下の 3 層のアプローチが考えられます。推奨は「層を組み合わせたハイブリッド方式」です。

3.1 スキル定義層（宣言的統合）

RSIDE はすでに .agents/skills/*.json によるスキル定義システムを持っています。 ここに Openship 操作専用のスキルを追加し、エージェントが「デプロイ」「ログ確認」「ロールバック」などを計画に組み込めるようにします。 

// .agents/skills/openship-deploy.json（概念例）
{
  "name": "openship-deploy",
  "description": "Openship でプロジェクトをデプロイする",
  "parameters": {
    "projectId": { "type": "string" },
    "branch": { "type": "string", "default": "main" },
    "environment": { "type": "string", "enum": ["production", "preview"] }
  },
  "permissions": ["deployment:write"]
}

3.2 ブリッジ層（実行統合）

RSIDE の Rust バックエンド（Tauri コマンド）に Openship 操作用モジュールを追します。 実装選択肢は以下の 3 通りです。

A. CLI ラッパー方式（最速実装）

既存の Agent Desktop ブリッジと同様に、openship CLI をサブプロセスとして呼び出します。 --json フラグで構造化出力を得て、RSIDE の UI にパースして表示します。 

openship --json deploy --project proj_xxx --watch
openship --json deployment logs dep_xxx
openship api /api/deployments/dep_xxx/build

B. REST API 直接呼び出し方式（柔軟性重視）

Rust 側から reqwest を使い、Openship の REST API を直接呼び出します。 SSE (Server-Sent Events) によるビルドログのリアルタイム表示も可能です。 API キーは OS キーチェーンに保存し、Rust 側でのみ使用します（RSIDE の既存セキュリティポリシーと一致）。 

// Rust（Tauri コマンド）概念例
#[tauri::command]
async fn openship_deploy(
  state: State<'_, OpenshipClient>,
  project_id: String,
) -> Result<DeploymentResult, String> {
  let res = state
    .post("/api/deployments")
    .json(&json!({ "projectId": project_id }))
    .send()
    .await
    .map_err(|e| e.to_string())?;
  res.json().await.map_err(|e| e.to_string())
}

C. MCP クライアント方式（将来性重視）

Openship は MCP (Model Context Protocol) サーバーを標準搭載しています。 RSIDE のエージェントが MCP クライアントとして Openship に接続すれば、549 のツールを直接利用できます。 ただし、RSIDE 側に MCP クライアント実装が必要であり、Phase 2 以降の討とするのが現実的です。

3.3 UI 統合層（体験統合）

RSIDE のエージェントパネル（Chat / Plan / Runtime の 3 タブ）に Openship 専用の表示領域を追加します。

  • Plan タブ: デプロイ計画に「Openship デプロイ」ステップを自動生成。承認フローで実行制御。
  • Runtime タブ: ビルドログのリアルタイムストリーム、デプロイ状態の可視化。
  • Chat タブ: /deploy, /logs, /rollback などのスラッシュコマンドを追加。

以下は、RSIDE 側から Openship 連携を利用する際の推奨フローです。

05具体的な実装ステップ

Phase 1: 最小限の CLI 連携（即座に動作）

  1. RSIDE の設定画面に Openship 接続情報を追加（API URL、Organization ID、PAT）。
  2. Rust バックエンドに openship_cli_path の検出ロジックを追加（Agent Desktop ブリッジと同様）。
  3. /deploy コマンドを実装: カレントワークスペースで openship init → openship deploy --json を実行。
  4. JSON 出力をパースし、デプロイ ID とステータスをエージェントパネルに表示。

Phase 2: REST API 連携（エクスペリエンス向上）

  1. Rust 側に OpenshipClient を実装（reqwest + トークン管理）。
  2. デプロイ進行状況のポーリング、または SSE によるリアルタイムログ表示を実装。
  3. プロジェクト一覧、デプロイ履歴、ロールバック操作を UI に統合。
  4. OS キーチェーンへのトークン保存を RSIDE の既存機構で再利用。

Phase 3: 計画立案と運用自動化（エージェントの本領発揮）

  1. スキル定義 openship-*.json を整備し、LLM がデプロイ計画を自動生成できるようにする。
  2. 「デプロイ前にテストを実行」「失敗時に自動ロールバック」などの複合スキルを追加。
  3. Openship のドメイン・SSL 状態確認ツールを統合し、運用監視も同一画面で行えるようにする。
  4. 将来的に MCP クライアントを検討し、Openship の 549 ツールへ完全アクセス。

06セキュリティと設計上の注意点

トークン管理

Openship の PAT (Personal Access Token) は RSIDE の既存方針に従い、OS キーチェーンにのみ保存します WebView から直接外部 API を呼ばず、必ず Rust 側を介して通信します。

スコープ設計

エージェントに与えるトークンの権限は最小限にします。 例: deployment:write と project:read のみ。 キャンセル・ロールバック・削除は admin スコープが必要なため、承認フローと組み合わせて用します。

パス検証

RSIDE はすでにワークスペース外への書き込みを拒否しています。 Openship 連携時も、デプロイ対象パスがワークスペース内にあることを Rust 側で検証し、 絶対パスや .. を含む引数を拒否します。

段階的自律性

RSIDE の Passive / Assistive / Autonomous 3 モードを Openship 操作にも適用します。 Passive ではステータス確認のみ、Assistive では個別承認付きデプロイ、Autonomous では計画に基づく連続実行、という粒度を維持します。

07まとめ

RSIDE 側から Openship を連携させ最も現実的な第一歩は、既存の Agent Desktop ブリッジ機構を拡張し、Openship CLI をサブプロセスとして呼び出す方式です。 これにより、最小限の追加実装で「エディタ → エージェント → デプロイ」の流れを同一ワークスペース内で実現できます。

中期的には Rust バックエンドからの REST API 直接呼び出しに移行し、リアルタイムログやプロジェクト管理を UI に統合することで、エクスペリエンスを大きく向上させられます。 さらにスキル定義と計画立案の整備により、LLM が「書く・任せる・確かめる」の一連を自律的に支援する環境が完成します。

最終的に MCP クライアント化を検討することで、Openship の 549 ツールへ完全にアクセスできるようになり、 RSIDE は単なる IDE ではなく、インフラ運用まで統合したエージェント駆動型開発環境へと進化します。
