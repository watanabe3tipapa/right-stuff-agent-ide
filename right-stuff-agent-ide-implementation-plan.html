本書は Right-Stuff Agent IDE の構想をまとめた実装設計書です。Phase 0 の実装は、Lexical ベースの既存コードを移行したものではなく、 Tauri 2.0 + React 18 + Monaco で新規に構築しています。LSP と DAP は v0.3.1 で実装済み、Apple Notes 連携は今後の候補です。 OpenAI 互換 LLM 接続、計画立案と承認、監査ログ、Openship 連携は実装済みで、現時点の実装範囲は README の「既知の制約とロードマップ」を参照してください。

01

コンセプトとビジョン

Right-Stuff Agent IDE は、Right-Stuff Editor の執筆・編集体験を UI ベースにしつつ、 Agent Desktop の OS アクセシビリティツリー操作能力を統合した、新しい形のエージェント駆動型 IDE です。

従来の AI エディタは「エディタ内で AI に質問する」モデルでしたが、Right-Stuff Agent IDE は 「エディタそのものがエージェントの作業台になる」モデルを採用します。 エージェントはエディタの UI を直接操作できるだけでなく、エディタ外のデスクトップアプリケーションとも連携し、 コード作成からテスト実行、ドキュメント整備、デプロイまでの一連のワークフローを一貫して支援します。

◆ コアビジョン

「書く、動かす、確認する」のサイクルを、エディタの中で完結させる。 エージェントがエディタの UI を直操作し、ファイルシステム、ターミナル、ブラウザ、 外部アプリケーションを横断して作業を進める。

統合の3本柱

執筆体験
Lexical ベースのリッチテキスト、Markdown 双方向編集、 ワークスペース管理、バージョン履歴、Apple Notes 連携を継承
エージェント操作
Agent Desktop の OS アクセシビリティツリー API を統合し、 エディタ UI と外部アプリの両方をエージェントが操作可能に
IDE 機能
ファイルエクスプローラ、ターミナル、デバッガ連携、 Git 統合、LSP 対応、マルチ言語サポート

なぜ Tauri 2.0 を推奨するか
Right-Stuff Editor は tinyjs を採用していますが、 Agent Desktop との統合では Rust レイヤーが必須です。 Tauri 2.0 は Rust コア + WebView フロントエンドの構成で、 Agent Desktop の Rust バイナリとの親和性が高く、 macOS のネイティブ機能を活かしやすい構成です。

エージェントモード切替

ステータスバーのエージェントモードインジケータをクリックすることで、以下のモードを切り替えます。

  • Passive ゴーストテキスト補完、インライン提案のみ。UI 操作なし。
  • Assistive 選択範囲の変換、チャット回答、ファイル内検索・置換を実行。
  • Autonomous エージェントがファイル作成、ターミナル実行、外部アプリ操作を自律実行。ユーザー承認フロー必須。

実装フェーズ

Phase 0: 基盤構築
期間: 2週間 / 優先度: 最高

Tauri 2.0 + React 18 のプロジェクトを新規に構築。Monaco エディタ、ワークスペース、 SQLite のバージョン履歴、Agent Desktop ブリッジを実装し、macOS で動作を確認。

Phase 1: Agent Desktop 統合基盤
期間: 3週間 / 優先度: 最高

Agent Desktop CLI を Rust レイヤーから呼び出すラッパーを実装。 スナップショット取得、アクション実行、エラーハンドリング、セッション管理を構築。 エージェントチャット UI に「外部アプリ操作」モードを追加。

追加: Openship 連携 (v0.2.0)
ローカルファースト / 優先度: 高

設計書のフェーズには含まれていなかったが、v0.2.0 で先行実装。 Deploy タブ、openship CLI の検出と REST フォールバック、デプロイ履歴・ログ・ロールバック、 PAT の OS キーチェーン保存、変更操作のネイティブ承認、監査ログ記録を追加。

追加: IDE コア機能 (v0.3.0)
クイックオープン / Git / ターミナル / 優先度: 高

設計書の Phase 2 のうち、クイックオープン (⌘P)、Git パネル、統合ターミナル (⌘J、portable-pty + xterm.js)、 ファイル検索を先行実装。ステータスバーの Git ブランチ表示と、ターミナル終了時の PTY クリーンアップも追加。

追加: スキルライブラリ (v0.3.4)
人間向けカタログ / ショーケース別窓 / マニフェスト書き出し

キュレーション済みのスキルを目的・リスク・パラメータ・マニフェストで読める形に整理し、 独立した skill-library ウィンドウで表示。利用可能なスキルは .agents/skills/<id>.json へ書き出せる。Git / ターミナル / デバッグは 設計カードとして扱い、未実装の操作を実行可能に見せない。

追加: LSP 拡張 (v0.3.3)
名前変更 / 参照検索 / コードアクション / シンボル検索

LSP クライアントに rename (F2)、参照検索 (⇧F12)、コードアクション、ワークスペースシンボル検索 (⌘T) を追加。 WorkspaceEdit をタブへ適用し、workspace/applyEdit にも対応。変換ロジックの単体テストを拡充した。

追加: LSP / DAP (v0.3.1)
補完 / 定義 / 診断 / デバッグ / 優先度: 高

LSP クライアントを追加し、固定レジストリの言語サーバーを Monaco の補完・定義ジャンプ・ホバー・診断に接続。 DAP クライアントを追加し、lldb-dap と debugpy による起動・停止・ステップ実行・ブレークポイント・ コールスタック・変数表示を Debug タブに実装。両者は Content-Length フレーミングの共通トランスポートを共用する。 あわせてツール検出 UI と、ワークスペース切替・終了時のセッション停止を追加。

セキュリティ設計

エージェント操作の安全性

承認フロー

Autonomous モードでは、以下の操作にユーザー承認を必須とします。

  • ワークスペース外のファイルへの書き込み
  • ターミナルでのコマンド実行（特に rm, curl | sh 等）
  • 外部アプリケーションの起動・操作
  • Git の push / force push
  • クリップボードへの機密情報の書き込み

データ保護

項目方針
原稿データワークスペースのローカルファイルにのみ保存。クラウド送信なし。
API キーmacOS Keychain（Keychain Services）に保存。
スナップショットメモリ上に一時保持。永続化はオプトイン。機密ウィンドウは自動マスク。
テレメトリ収集なし。完全にオプトインのクラッシュレポートのみ。
パス検証バックエンドでワークスペース外パスを拒否。.right-stuff 配下への直接アクセスも禁止。

プライバシー設計

Agent Desktop のスナップショットにはデスクトップ上の機密情報が含まれる可能性があります。 Right-Stuff Agent IDE では以下の対策を講じます。

  • スナップショットはセッション中のみメモリ保持。SQLite への永続化はユーザーが明示的に許可した場合のみ。
  • 銀行アプリ、メールクライアント等の機密ウィンドウは自動検出し、スナップショットから除外。
  • LLM へのコンテキスト送信時は、スナップショットデータを最小化し、ファイルパス・ユーザー名を匿名化。
  • エージェントの全操作ログはローカルに保存。ユーザーが確認・削除可能。

リスクと対策

リスク影響対策
Agent Desktop の権限要件 macOS アクセシビリティ権限がないと動作しない 初回起動時に権限ガイドを表示。権限なしでエディタ単体で動作するフォールバック。
スナップショットの機密情報漏洩 デスクトップの機密データが LLM に送信される 機密ウィンドウ自動マスク、送信前匿名化、オプトイン制。
エージェントの誤操作 ファイル削除、誤った Git 操作等 危険操作の承認フロー、undo 履歴、バックアップ自動化。
macOS バージョン差異 macOS 11 以降で挙動が異なる macOS 11 以降を対象に検証。Agent Desktop が API 差異を抽象化。
パフォーマンス低下 スナップショット取得が重い キャッシュ戦略、差分スナップショット、非同期処理。
LSP 互換性 言語サーバーごとに挙動が異なる vscode-languageserver-protocol 準拠。主要言語サーバーでテスト。

今後の展望

  • 協調エージェント: 複数のエージェントが同時に異なるファイル・タスクを並行処理。
